20260424RW: Improvements made to cursor function, most likely could continue to be improved upon but the cursor itself is a testing function and will not be in the final implementation
so it is not a high priority. It is used primarily to fine-tune equations for touch accuracy.

Interrupt hangs during screen changes have been nullified with two implementations: a "gate" for the interrupts that prevent them from firing if the screen is currently drawing (no
communication issues over the SPI bus), and the TouchInterrupt_Helper has been added to the end of these drawing functions. My theory is that for some reason, the LCD drawing was causing
the pins (specifically Y- since it is the interrupt) to misbehave, and this resulted in the interrupt getting stuck or not working. My manually resetting the pin assignment during each
screen change, this will not happen. Possibly overkill, but using the function does not result in any severe/noticeable downtime or lag at this time.

Modifications were made to the equations based on the cursors tracking to allow the pixel values to stretch all the way to the edge of the screens, rather than getting cut off at around
~15 pixels from the edges. This most likely has something to do with how the calibration circles treat the voltage readings they receive (i.e., highest voltage reading is ideally ~15 pixels
to the left of the right edge per calibration method), so to compensate the screen "size" was extended by 10 for both the width and height.

20260423RW: Touch screen allows for calibration to be performed (seemingly correctly, so equations are good). Most of the time, an operating mode screen can be chosen after calibration is completed. If a preset is chosen,
it will immediately launch to display screen. If CUSTOM is chosen, it will enter Number of Displays screen. From here, there is an LED to register touches and a cursor implemented to track accuracy of calibration. There is an error in the
interrupt, as I suspect it is misfiring during transitionary screens. From the second calibration circle screen to the calibration complete screen, it seems that if the screen is tapped, it will "lock out" of the interrupt, not allowing the user to
make a selection on the next screen. This also means the LEDs and the cursor do not work. When this does not occur, a selection can be made, and the LEDs will work sometimes. The cursor appears to never work. If CUSTOM is selected, the touch
interrupt stops working on the number of displays screen.

It seems the ultimate root issue here stems from the interrupt not correctly firing, which I suspect is due to pin configuration and how the coordinate code is operating. My guess is that when measuring the values,
the pins are not being re-initialized in the correct manner, so it will trigger the interrupt once more, and then never again.

Main tasks that must be fixed:
1. Improve the WaitForTouchRelease function. If this is truly causing interrupt misfires when the screen changes, then the program is not fully operable/is not detecting the release correctly. This could possibly be an issue with
touch_baseline or the MARGIN value being too large/too small.
2. Figure out how to re-enable interrupts consistently after measurements are taken. In theory, the callback function used for the interrupts should allow the interrupt enable flags to be automatically cleared and set 
when it is called, but this may need to be done manually in the code as well since it is not triggering. If this manual fix is not possible/does not work, it is most certainly a pin configuration issue, and the Y_MINUS interrupt is never
properly triggering because that pin is not being reset to the state it needs to be in for the interrupt.
3. Get the cursor function to work (hopefully should automatically begin working with #2 is fixed)

Updates:
Moving the X and Y coordinate readings will offer consistent interrupt measurements. The cursor however is very slow, and sporadic. Not as precise as it is on the msp430.
In addition, the logic behind why the code works is flawed. Should be remedied to be as robust as possible before moving on.
